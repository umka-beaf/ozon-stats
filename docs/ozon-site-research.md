# Исследование: слой поверх ozon.ru

Дата: 2026-11-10. Источник — живой сайт `www.ozon.ru` под авторизованной сессией,
DOM и ответы `composer-api.bx`. Цель — понять, какие данные уже есть в разметке,
что придётся вычислять и насколько реально сделать светлую/тёмную тему сайта.

## 1. Выдача каталога

Страница: `/category/chay-kofe-kakao-9370/?text=кофе` (16 карточек в первом экране,
дальше `infiniteVirtualPaginator`).

| Что | Наблюдение |
|---|---|
| Корень карточки | `.tile-root` — стабильный класс, не хешированный |
| Цена | `span` с текстом `^\d[\d\s]*\s*₽$`; классы хешированные (`c35_6_4-*`) |
| Старая цена | отдельный элемент с `text-decoration: line-through` |
| Скидка | текстом `−65%` |
| Промо-метки | «Распродажа», «Вау-цены», «0% до 140 дней», «Хит продаж» |
| Дефицит | «3 413 ед осталось» |
| Название | строка карточки, не всегда внутри `<a>` |

Замеры на 16 карточках:

- зачёркнутая цена — **16/16**;
- бейдж `−NN%` — **16/16**;
- промо-метка — **16/16**;
- «N ед осталось» — 3/16;
- размер (кг/г/мл/л/шт) парсится из названия — **13/16 (81%)**.

Примеры названий: «Кофе в зернах Натти, 1 кг», «…800 г», «Дрип кофе … 24шт*10гр»,
«Молоко … 1 л х 12 шт». Упаковка «х 12 шт» — множитель, его нужно учитывать.

Вывод: цена за единицу на выдаче считается эвристикой по названию, точность
~80%. Отдельного поля с весом/объёмом в карточке выдачи нет (проверено, в JSON
`composer-api` для выдачи товарных объектов нет — плитки рендерятся сервером в HTML).

## 2. Карточка товара (PDP)

Проверено на двух товарах: кофе (`…natti-1-kg-715106535`) и молоко
(`…vologzhanka-…-1569065798`).

Блок `[data-widget="webShortCharacteristics"]` и `[data-widget="webCharacteristics"]`
содержат структурированные характеристики:

- кофе: `Вес товара, г` = 1000, `Единиц в одном товаре` = 1;
- молоко: `Объем, мл` = 1000, `Единиц в одном товаре` = 1.

`script[type="application/ld+json"]` (schema.org Product) вес/объём **не содержит** —
только бренд, описание, рейтинг. Значит, точная цена за кг/л берётся только из
характеристик DOM (или виджетов composer-api для PDP).

Полезные виджеты PDP: `webPrice`, `webShortCharacteristics`, `webCharacteristics`,
`webSale`, `webMarketingLabels`, `bigPromoPDP`, `webStickyColumn`.

## 3. Главная и реклама

Виджеты, дающие крупные малоинформативные блоки:

| Виджет | Что это | Замер |
|---|---|---|
| `advBanner` | рекламные баннеры | 13 шт. по 300 px на главной |
| `wallpaper` | промо-подложка | блок ~2400 px высотой |
| `bannerCarousel` | карусель на PDP | есть на карточке товара |
| `bigPromoCounterNavbar` | промо-навбар | главная |
| `alertPopup` | всплывающее уведомление | главная |
| `bubbleRateBoughtItem` | «Поблагодарите продавца» | главная |

Все — стабильные `data-widget`-атрибуты, скрываются CSS/JS без привязки к хешам.

## 4. Тёмная тема: устройство стилей Ozon

Факты с главной страницы:

- `prefers-color-scheme: dark` в ОС — `true`, сайт при этом светлый;
- в CSS **нет** ни одного `@media (prefers-color-scheme)`, ни селекторов темы;
- `:root` объявляет **1053** CSS-переменные;
- в правилах реально используются **283** переменные, из них **178** — цветовые;
- семантические имена есть: `--textPrimary`, `--textSecondary`, `--textTertiary`,
  `--ozTextPrimary`, `--ozBGSecondary`, `--ozBGPrimary`, `--layerFloor1`,
  `--graphicNeutral`, `--ozSeparator`, `--textOriginalpriceAvailable` и т.п.;
- есть «инвертированные» токены (`--textPrimaryInverted`, `--bgSecondaryInverted`) —
  они для светлого текста на тёмных поверхностях, их трогать нельзя.

### Подводный камень специфичности

Переопределение на `html { --token: … }` **не работает**: `:root` имеет
специфичность (0,1,0) против (0,0,1) у `html`. Тема обязана писаться как
`:root { … }` (или `html:root`).

### Пилот

Сгенерировал ~248 переопределений: все белые токены → `#1b1d21`, все почти чёрные
текстовые → `#e8eaed`, серые → полупрозрачный белый.

Результат:

- доля тёмного текста среди листовых элементов: **67% → 22%**;
- светлых фонов осталось **174** — плитки товаров остались белыми.

Вывод: токены закрывают шапку, меню, фон страницы, но **не карточки товаров**.
Тема = два слоя:

1. курируемый набор семантических токенов (~40);
2. отдельные правила для `.tile-root` и внутренних блоков (текст, фон, рамки).

Полностью автоматический инверт (`filter: invert`) покрывает всё, но требует
контр-инверта картинок и даёт грязные цвета бренда — как запасной режим, не основной.

## 5. Ограничения исследования

- Классы Ozon хешированные (`c35_6_4-*`), меняются между релизами → селекторы
  строить только на `data-widget`, `.tile-root`, ссылках `/product/` и текстовых
  паттернах.
- Сайт отдаёт antibot-челлендж на «холодные» сессии — проверки делались в уже
  авторизованной вкладке.
- Есть A/B-параметры (`?__rr=1`, `?sh=…`) — разметка может отличаться между
  пользователями.
- Цена за единицу по названию покрывает ~80% карточек; для точности нужна
  подгрузка PDP (сеть + кеш), это отдельное решение по нагрузке.
- Статусы заказов и остальные данные панели к этому документу не относятся.

## 6. Что это даёт для планирования

1. Скрытие баннеров — самый дешёвый и предсказуемый выигрыш (стабильные виджеты).
2. Скрытие зачёркнутых цен — одна CSS-строка на карточку, обратимо.
3. Цена за кг/л/шт: MVP — эвристика по названию; точный режим — PDP + кеш.
4. Тема сайта: токены + правила для плиток; нужен ручной QA по страницам
   (главная, выдача, PDP, корзина, заказы).
